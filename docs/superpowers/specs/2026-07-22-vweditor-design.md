# vwEditor 설계 문서 (MVP)

- 날짜: 2026-07-22
- 목표: EMEditor처럼 **10GB+ CSV/TSV/텍스트 파일을 여는 순간 즉시** 테이블로 확인하는 빠른 뷰어
- 배포: **단일 .exe, Windows 즉시 실행** (설치 불필요)
- 리서치 근거: [.readme/20260722_대용량_에디터_리서치.md](../../../.readme/20260722_대용량_에디터_리서치.md)

## 스코프

### MVP에 포함
- 파일 열자마자 즉시 표시 (2단계 로딩)
- 구분자로 테이블 분리 (콤마/탭/파이프/세미콜론 + 커스텀)
- 구분자 자동 감지 (확장자 + 내용) + 수동 변경
- 헤더 자동 감지 + 토글 (헤더 있음/없음 파일 모두)
- 인코딩 자동 감지 (UTF-8 / CP949 / UTF-16 BOM) + 수동 변경
- 라인 번호 표시
- 헤더 위 컬럼 번호
- 가상 스크롤 (수백만 행)
- 백그라운드 인덱싱 + 진행률 상태바 + 중단/이어서 토글

### MVP에서 제외 (다음 버전)
- 찾기 / 찾아 바꾸기
- 편집·저장
- 정렬·필터
- AVX512 SIMD (병목은 I/O·렌더링이라 불필요)
- rope 자료구조 (뷰 위주라 단순 offset 인덱스가 적합)
- 외부 파일 변경 감지 (스냅샷처럼 취급)

## 성공 기준

| 항목 | 목표 |
|------|------|
| 파일 열림 → 첫 화면 | 10GB도 **0.5초 이내** (1단계, 앞부분만) |
| 스크롤 프레임률 | 60fps (보이는 행 + 버퍼만 파싱) |
| 전체 인덱싱 (백그라운드) | 10GB SSD 기준 수 초~십수 초, UI 논블로킹 |
| 메모리 | 파일 크기 무관 낮게 (mmap + offset 인덱스만 상주) |
| 배포 | `cargo build --release` → 단일 .exe |

## 기술 스택

```
Rust
egui + eframe            — GUI, 단일 .exe 네이티브
egui_extras::TableBuilder — 가상 스크롤 테이블
memmap2                  — 파일 메모리 매핑
csv-core                 — no_std, alloc 없는 필드 파싱
encoding_rs              — UTF-8 / CP949(EUC-KR) / UTF-16 디코딩
std::thread + Arc/Atomic — 백그라운드 인덱싱
```

## 아키텍처: 4개 모듈

```
┌─────────────────────────────────────────────┐
│  app (egui)  — UI 루프, 상태, 이벤트          │  main.rs / app.rs
└───────────┬─────────────────────┬───────────┘
            │ 읽기 요청            │ 진행 상황
            ▼                     ▼
┌───────────────────┐   ┌───────────────────────┐
│  index            │◀──│  백그라운드 인덱싱 워커  │
│  줄 offset 인덱스   │   │  (std::thread)         │
└─────────┬─────────┘   └───────────────────────┘
          │ offset 조회
          ▼
┌───────────────────┐   ┌───────────────────────┐
│  source (mmap)    │──▶│  parse (csv-core)     │
│  memmap2 파일 매핑 │   │  인코딩 디코딩 + 필드 분리│
└───────────────────┘   └───────────────────────┘
```

### 모듈 책임과 인터페이스

**`source`** — memmap2로 파일을 매핑. "바이트 범위 → 슬라이스"만 담당. 파일이 CSV인지 모름.
- `open(path) -> Source`
- `slice(range: Range<u64>) -> &[u8]`
- `len() -> u64`

**`index`** — 줄 시작 offset 배열. 백그라운드 워커가 append. UI는 "줄 번호 → offset"을 O(1) 조회. 스레드 안전.
- `offset(row: usize) -> u64` (읽기, UI에서)
- `push(offset: u64)` (쓰기, 워커에서)
- `len() -> usize` (지금까지 인덱싱된 줄 수)
- 공유: `Arc<RwLock<Vec<u64>>>` (또는 append-only 구조), `status: Arc<Mutex<IndexStatus>>`, `cancel: Arc<AtomicBool>`
- 메모리: 줄당 u64 8B. 1억 줄 = 800MB. 나중에 압축 여지만 남김(MVP는 단순 Vec).

**`parse`** — 바이트 슬라이스 하나 → (디코딩) → 구분자로 필드 분리. 구분자/헤더/인코딩 감지 로직 포함.
- `detect_encoding(head: &[u8]) -> Encoding`
- `detect_delimiter(path, head) -> u8`
- `detect_header(rows) -> bool`
- `split(line: &[u8], enc, delim) -> Vec<String>`

**`app`** — egui UI. 위 셋을 조합해 보이는 행만 렌더. 상태(스크롤 위치, 헤더 on/off, 구분자, 인코딩) 소유. index에만 offset을 물어보고 source byte를 직접 안 만짐.

**핵심 원칙**: `index`가 `source`와 `app` 사이의 유일한 다리.

## 2단계 로딩 & 상태 전이

```
       파일 열기
          │
          ▼
   ┌─────────────┐   1단계: 앞부분(창 높이 × 5행)만 즉시 스캔
   │  Priming    │   → 화면에 데이터 즉시 표시 (0.5초 이내)
   └──────┬──────┘   → 이 앞부분으로 인코딩/구분자/헤더 감지
          │
          ▼
   ┌─────────────┐   2단계: 파일 끝까지 개행 offset 스캔 (백그라운드)
   │  Indexing   │   상태바: "인덱싱 중... 3.2 / 10.4 GB (31%)  [중단]"
   └──┬───────▲──┘   스크롤: 지금까지 인덱싱된 줄까지만
      │       │
 [중단]│       │[이어서 읽기]  (같은 버튼 토글)
      ▼       │
   ┌─────────────┐   상태바: "일시정지 — 3.2 / 10.4 GB (31%)  [이어서 읽기]"
   │  Paused     │   스크롤: 읽은 데까지만
   └─────────────┘
          │ (Indexing이 끝까지 도달)
          ▼
   ┌─────────────┐
   │  Complete   │   상태바: "완료 — 12,345,678 행"  스크롤: 전체 자유
   └─────────────┘
```

- **중단/이어서 = 하나의 버튼 토글.** 워커는 "다음에 읽을 offset"을 유지하므로 재개는 그 offset부터 이어감. 인덱스는 append-only.
- 완료되면 버튼 사라짐.

### 한 프레임에서 화면 그리기 (데이터 흐름)

1. egui가 스크롤 위치 → `first_visible_row` 계산
2. 렌더 범위 = `[first_visible_row - 버퍼 .. first_visible_row + 화면행수 + 버퍼]` (버퍼 = 화면행수 정도, 예: 위아래 각 50행 — 구현 시 튜닝)
3. 각 행 `r`: `index.offset(r)`, `index.offset(r+1)` → byte 범위
4. `source.slice(start..end)` → 바이트 슬라이스
5. 디코딩(인코딩) → 문자열 → `parse.split()` → 필드 → egui 셀
6. 범위 밖 행은 파싱조차 안 함 (10GB여도 가벼움)

### 스레드 간 공유
- 인덱스: `Arc<RwLock<Vec<u64>>>` (워커 쓰기, UI 읽기)
- `cancel/pause: Arc<AtomicBool>`
- `status: Arc<Mutex<IndexStatus{ bytes_done, total_bytes, phase }>>`
- 워커 살아있는 동안 매 프레임 egui repaint 요청, 상태바 갱신

## 자동 감지

### 인코딩 (BOM → UTF-8 → CP949)
1. **BOM 검사**: `EF BB BF`→UTF-8, `FF FE`→UTF-16LE, `FE FF`→UTF-16BE. 있으면 확정.
2. BOM 없으면 **UTF-8 유효성 검사** → 유효하면 UTF-8
3. UTF-8로 깨지면 → **CP949**
4. 드롭다운(UTF-8 / CP949 / UTF-16LE / UTF-16BE)으로 사용자 덮어쓰기
- **인덱싱 시 주의**: UTF-16은 개행이 2바이트(`0A 00`)라 인덱싱 전에 BOM으로 인코딩 확정 후, UTF-16이면 2바이트 개행 스캔. UTF-8/CP949는 `0A` 단일 바이트 공통이라 동일.

### 구분자 (확장자 → 내용)
1. **확장자 우선**: `.tsv`/`.tab`→탭, `.csv`→콤마, `.psv`→파이프
2. **애매하면(.txt 등) 내용 분석**: 앞부분 여러 줄에서 후보(`,` `\t` `|` `;`)별 "줄당 등장 횟수" → 가장 일관된(분산 낮은) 것 선택
3. 아무것도 일관되지 않으면 → 단일 컬럼 텍스트 뷰
4. 드롭다운으로 사용자 덮어쓰기

### 헤더 (첫 줄 vs 나머지 타입 비교)
- 첫 줄이 전부 비수치인데 아래에 수치 필드 존재 → 헤더
- 첫 줄도 아래와 타입 동일 → 애매 → **헤더 ON**(안전 기본값)
- 체크박스로 즉시 토글 (오판 대가 작음)

## UI 레이아웃

```
┌────────────────────────────────────────────────────────┐
│ [파일 열기]  구분자:[,▾]  인코딩:[UTF-8▾]  ☑헤더  파일명 │  상단 툴바
├─────┬──────────────┬──────────────┬─────────────────────┤
│  #  │ 1 name       │ 2 age        │ 3 city              │  헤더행(고정)
├─────┼──────────────┼──────────────┼─────────────────────┤
│  1  │ Alice        │ 30           │ Seoul               │  라인번호+데이터
│  2  │ Bob          │ 25           │ Busan               │  (가상 스크롤)
├─────┴──────────────┴──────────────┴─────────────────────┤
│ 인덱싱 중... 3.2 / 10.4 GB (31%)  [중단]   행 4,201,933  │  하단 상태바
└────────────────────────────────────────────────────────┘
```
(위 상태바는 "인덱싱 중" 순간. 일시정지 시 `[이어서 읽기]`, 완료 시 버튼 사라지고 "완료 — N 행" — 상태 전이 섹션 참조)

- 상단: 파일 열기, 구분자 드롭다운, 인코딩 드롭다운, 헤더 토글, 파일명. 감지 결과 반영 + 덮어쓰기.
- 본문: `egui_extras::TableBuilder`(가상 스크롤 내장). 맨 왼쪽 `#`=라인번호(고정 폭), 헤더행 sticky, 헤더 위 컬럼번호(1,2,3...). 컬럼 폭 자동 + 드래그.
- 하단: 진행 텍스트 + 중단/이어서 버튼 + 총 행 수.

## 에러 처리

- 파일 없음/권한 없음 → 상태바 에러, 크래시 안 함
- 빈 파일 → 빈 테이블, "0 행"
- 유효하지 않은 바이트 → 손실 없이 표시(`from_utf8_lossy` 유사), 파싱 계속
- 아주 긴 줄/줄마다 다른 필드 수 → 있는 만큼 표시, 크래시 안 함
- 외부 파일 변경 → MVP는 미감지(스냅샷 취급), 문서에 명시

## 테스트 (TDD)

- `parse`: 각 구분자, 따옴표 안 구분자(`"a,b",c`), 빈 필드, 개행(`\n`/`\r\n`), 인코딩별 디코딩 — 순수 함수, 단위테스트
- 감지: 인코딩(UTF-8/CP949/BOM), 구분자, 헤더 유무 샘플
- `index`: 작은 알려진 파일에서 offset이 정확한 줄 시작을 가리키는지
- `source`: mmap 슬라이스 경계
- 대용량: 합성 파일(수 GB)로 수동 스모크 테스트 (첫 표시 시간, 스크롤 fps, 인덱싱)
