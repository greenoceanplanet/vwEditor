# 편집 모드 + 저장(인코딩 변환) + Undo + 성능 수정

- 날짜: 2026-07-23
- 목적: 뷰 전용 뷰어에 편집 기능을 붙이고, 인코딩 변환 저장·Ctrl+Z·단축키·컬럼 연산
  성능까지 마무리한 작업 정리

## 한 줄 요약

mmap 읽기 전용이던 대용량 뷰어에 **편집 모드**를 추가했다. 텍스트 모드는 자유 편집,
세퍼레이터 모드는 셀 편집. 드래그·Shift+클릭 범위 선택, 통삭제/통붙여넣기, 우클릭 메뉴,
**Ctrl+Z(100단계)**, Ctrl+C/X/V, 컬럼 전체 복사, **인코딩 변환 저장**(UTF-8/CP949/
UTF-16LE·BE + BOM)을 지원한다. 작업 중 **컬럼 복사 634배 가속**(33.6초→53ms)과
**정렬에도 영향을 주던 파서 버그**를 함께 잡았다. 브랜치 `feat/editing-and-save`,
테스트 223개 통과, 빌드 경고 2(모두 dead_code).

---

## 1. 편집 모델 (핵심 결정)

**편집 모드 진입 시 파일 전체를 `Vec<String>`(줄 배열)로 RAM에 로드한다.**

- 뷰 전용 경로(mmap + LineIndex)는 그대로 두고, `Document.edit: Option<EditBuffer>`가
  Some이면 렌더·정렬·저장이 모두 `EditBuffer`를 진실의 원천으로 삼는다.
- 근거: emeditor도 편집 시 행수 비례 메모리를 쓴다. "램 절약 과하게 마라"는 이전 방침과
  일치. piece table / mmap 조각 편집은 현재 요구엔 과임(YAGNI).
- 한 줄 = 한 논리 행. 이 앱의 모든 것(행 번호, 셀, 정렬, 표/텍스트 렌더)이 이미 줄
  단위라 자연스럽게 맞는다. rope 크레이트는 셀/행/정렬과 임피던스 불일치라 채택 안 함.
- **불변식: `lines[i]`에는 절대 개행이 없다.** 개행은 `newline` 필드로 따로 관리하고
  저장할 때만 붙인다. 셀 값에 개행이 들어오면 공백으로 치환(`sanitize_cell_value`).

### 편집 모드에서 정렬 = 실제 행 재배치

사용자 결정: "정렬도 편집 중 하나다." 그래서 편집 모드의 정렬은 permutation 뷰 매핑이
아니라 **`lines`를 물리적으로 뒤섞는 1회 편집**이다.

- 정렬 후 행을 삽입하면 그 자리에 그대로 남는다(재정렬 안 함).
- "정렬 유지/해제", "재정렬 시점" 같은 고민 자체가 사라진다. permutation 인덱스 어긋남
  문제가 존재하지 않는다.
- 뷰 전용 모드는 mmap을 재배치할 수 없으므로 기존 permutation 방식 유지.

## 2. 기능

### 텍스트 모드 (구분자 None)
- 문자 단위 커서/선택, 타이핑, Enter(줄 분할), Backspace(줄 병합), Delete
- 방향키·Home·End, Shift+이동으로 선택 확장, Ctrl+A
- 드래그 선택, **Shift+클릭 범위 선택**, 우클릭 메뉴(잘라내기/복사/붙여넣기/삭제/전체 선택)
- **커서 위치 매핑이 정확하다**: 같은 galley로 그리고 같은 galley로 좌표를 계산해
  한글/CJK/탭에서도 캐럿이 글자와 어긋나지 않는다.

### 세퍼레이터 모드 (표)
- 셀 더블클릭 → 인라인 편집 → Enter 커밋 (Esc는 취소)
- 셀 사각 범위 드래그 선택, **Shift+클릭 범위 선택**
- 우클릭 메뉴: 복사/잘라내기/붙여넣기/셀 내용 지우기/행 삽입(위·아래)/행 삭제
- **Ctrl+C/X/V 키보드 단축키** — 우클릭 메뉴와 같은 경로(구현 하나)
- **외부 앱(엑셀) → 뷰어 붙여넣기 지원** (`Event::Paste`의 실제 시스템 클립보드 사용)
- **컬럼 전체 복사**: 헤더 클릭으로 컬럼 선택 후 복사 → 헤더 제외 데이터만 세로로

### Undo (Ctrl+Z, 100단계)
**변경분만 기록한다** — 10GB 파일에서 스냅샷은 불가능하기 때문.

```rust
enum EditOp {
    Replace(Vec<(usize, String)>),        // 값 변경: 이전 줄 내용만
    RemoveInserted { at, count },          // 삽입 취소
    ReinsertRemoved { at, lines },         // 삭제 복원
    Reorder { inverse, data_start },       // 정렬 취소(역순열)
    Batch(Vec<EditOp>),                    // 한 동작 = Ctrl+Z 한 번
}
```
- `push`는 **편집 직전에** 호출해 이전 상태를 담는다. `undo()`는 LIFO.
- 12개 변이 지점 전부에 기록이 있음을 리뷰에서 전수 확인.
- 정렬도 되돌려진다(`inverse_of`로 역순열 생성).
- 범위를 벗어난 인덱스는 조용히 건너뛴다(패닉 없음).

### 저장 / 다른 이름으로 저장
- 인코딩 변환: UTF-8 / CP949 / UTF-16LE / UTF-16BE + BOM 선택(CP949는 BOM 없음)
- 개행도 대상 인코딩으로 재인코딩(UTF-16은 개행이 2바이트)
- 임시 파일(`<대상>.tmp`)에 다 쓴 뒤 `rename`으로 원자적 교체. 실패 시 임시 파일 삭제,
  원본 보존.
- dirty 경고: 편집 모드 이탈 / 다른 파일 열기 / **창 닫기**

## 3. 성능 수정 (사용자 보고 → 634배)

**증상:** "특정 컬럼하려고 하면 너무 오래 걸려. 지나치게 오래 걸려"

**원인:** 컬럼을 선택하면 대상 범위가 전체 행이 되는데, `cells_to_tsv`/`clear_cells`가
행마다 `split_fields`를 불렀다. `split_fields`는 행마다 **csv_core 리더를 새로 만들고
버퍼 Vec 두 개를 할당한 뒤 그 행의 모든 필드를 String으로** 만든다 — 컬럼 하나만
필요한데도.

**해결:** 정렬 최적화 때 만들어 둔 무할당 `parse::field_slice`를 재사용.

| 작업(200만 행) | 이전 | 이후 |
|---|---|---|
| 컬럼 복사 | 33,586 ms | **53 ms** (~634배) |
| 컬럼 지우기(이미 빈 컬럼) | 32,485 ms | **36 ms** |
| 컬럼 지우기(값 있음) | 34,121 ms | 24,244 ms |

마지막 항목은 값을 비우면 줄을 다시 조립해야 해서 이 방식으론 못 줄인다. 100만 행 초과
시 **확인 다이얼로그**로 막아 뒀다(`BIG_COLUMN_OP_ROWS`). 후속 아이디어: `field_slice`의
바이트 위치로 `String::replace_range` 제자리 치환.

### 덤으로 잡은 파서 버그 (정렬에도 영향)

`parse::field_slice`가 **따옴표를 만나면 위치와 무관하게 토글**하고 있었다. 그래서
`5" pipe,10,X` 같은 인치 표기 데이터에서 뒤따르는 구분자를 삼켜 필드를 병합했다.
이 함수는 **정렬 키 추출에도 쓰이므로 정렬도 조용히 틀리고 있었다.**

리뷰에서 실제 csv-core와 대조 검증:
- 동치성 퍼즈 245만 건 → 불일치 0
- 정렬 영향 전수 비교 59,046쌍 → **이전에 맞던 게 틀려진 경우 0건, 틀리던 게 맞아진
  경우 5,074건** (순수 개선)

정렬 테스트에 따옴표 데이터가 **하나도 없어 vacuous하게 통과**하고 있던 것도 발견해
회귀 테스트를 추가했다.

## 4. 아키텍처

### 신설
- **src/edit.rs** (egui-free): `EditBuffer{lines,dirty,newline,undo}`, `load_edit_buffer`,
  텍스트 연산(`insert_char`/`insert_str`/`split_line`/`delete_range`/`backspace`/
  `selection_text`), 셀 연산(`set_cell`/`clear_cells`/`insert_row`/`remove_row`),
  클립보드(`cells_to_tsv`/`paste_tsv`), `apply_permutation`, undo(`EditOp`/`UndoStack`/
  `inverse_of`)
- **src/save.rs** (egui-free): `SaveOptions`, `encode_bytes`, `write_file`(임시파일+rename)

### 수정
- **src/parse.rs**: `join_fields`(CSV 인용 규칙) 추가, `field_slice` 따옴표 버그 수정
- **src/sort.rs**: `sort_lines`(인메모리 다중 정렬 — mmap 경로와 동일 키 인코딩),
  키 함수 `pub(crate)` 승격
- **src/app.rs**: `Document.edit`, 편집 UI 전반, 저장/확인 다이얼로그, 메뉴, undo 배선
- **src/source.rs**: 테스트용 `from_bytes_for_test`, owned 바이트 지원

## 5. 리뷰에서 잡힌 주요 결함 (기록용)

작업 방식은 subagent-driven — 태스크마다 구현자 + 리뷰어를 따로 띄웠고, 리뷰가 실제
결함을 여러 건 잡았다.

| 심각도 | 결함 | 해결 |
|---|---|---|
| **Critical** | 저장 후 mmap이 낡은 상태로 남아, 저장→편집 모드 끄기 하면 **저장 전 내용으로 되돌아감**(dirty가 이미 false라 경고도 없음) | `repoint_source_after_save`로 Source 재생성 + 인덱서 재시작 |
| Important | Tab 키로 텍스트 줄에 포커스가 가면 **모든 타이핑이 삼켜져 편집 불가** | non-focusable Sense + `surrender_focus` (둘 다 필요 — `context_menu`가 내부적으로 focusable sense를 union함) |
| Important | 드래그 선택에 origin 추적이 없어 표 밖에서 누른 채 들어오면 선택이 끌려감 | `cell_drag_active` 래치 + `&& primary_down` 게이트 |
| Important | 그 수정이 만든 회귀 — `is_pointer_button_down_on()`이 버튼 무관이라 **우클릭이 다중 셀 선택을 무너뜨림** | `&& primary_down` 게이트 추가 |
| Important | 창 닫기(X/Alt+F4) 시 dirty 버퍼가 경고 없이 소실 | `CancelClose` + PendingAction |
| Important | 저장 실패 시 상태바 dirty 표시가 사라짐(exclusive else-if) | 에러를 추가 세그먼트로 |
| Important | 컨텍스트 메뉴 열린 채 Ctrl+A 하면 방금 만든 선택이 지워짐 | `secondary_clicked()` 엣지로 게이트 |
| Important | 셀 값에 개행이 들어가면 `lines[i]` 불변식 깨짐 | `sanitize_cell_value` |

## 8. 다음 요청 (착수 전)

사용자가 새로 요청한 항목:
1. 찾기/바꾸기
2. 찾기 결과에 해당하는 행을 **별도 문서로 추출**
3. **멀티 탭** — 지금은 `App.doc: Option<Document>` 하나뿐. `Vec<Document>` + 활성
   인덱스로 바꾸고 렌더/편집/저장 경로가 활성 문서를 보게 해야 함. 2번과 4번의 토대.
4. **드래그 앤 드롭으로 파일 열기** — 다수를 끌어오면 여러 탭으로 동시 병렬 오픈

의존 순서: 3(멀티 탭) → 2(추출=새 탭), 4(다중 오픈=여러 탭). 1은 독립적.

## 9. 미해결 / 알려진 제약

- 컬럼 지우기(값 있음)가 200만 행에 ~24초 — 확인 다이얼로그로 완화, 근본 개선은 후속
- undo 후에도 항상 dirty=true (저장 시점 내용으로 되돌려도 "변경됨" 표시)
- redo 없음, 표 모드 Ctrl+A 없음
- IME 조합(한글) 미처리 — 조합 중 표시 안 됨(완성 문자는 정상 입력)
- 캐럿 자동 스크롤 없음 — 화면 밖으로 방향키 이동 시 캐럿이 안 보임
- 탭 문자 입력 불가(`Event::Text`가 제어문자를 거름)
- 저장할 때마다 재인덱싱 — 대용량에서 CPU 소모
