## 1. 병렬 인덱싱 (rayon + memchr SIMD)

### 동기
기존 `spawn_indexer`는 백그라운드 스레드 **하나**로 파일을 8MB 청크씩 처음부터 끝까지
순차 스캔하며 개행 offset을 찾았다. 7GB면 코어 하나가 7GB를 전부 훑어야 해 느리다.
EMEditor는 모든 코어로 파일을 구간별로 나눠 동시에 스캔해 7GB를 0.7초에 연다.

개행 스캔은 완벽히 병렬화 가능(embarrassingly parallel)하다: 파일을 구간으로 나눠
각 구간에서 독립적으로 개행을 찾은 뒤 구간 순서대로 이어붙이면 순차 스캔과 동일한
offset 배열이 나온다.

### 설계 (docs/superpowers/specs/2026-07-22-parallel-indexing-design.md)
- **scan_segment**: 한 구간 `[seg_start, seg_end)`을 스캔하는 순수 함수. 담당 규칙 —
  "개행의 **다음 위치**(줄 시작)가 `[seg_start, seg_end)` 안인 개행만" 처리. 첫 줄
  시작(0)은 구간 0만 push. 이 규칙 덕에 **구간 concat = 순차 scan_offsets(정답지)**가
  정확히 성립(중복/누락 없음).
- **merge_segments**: 정상완주와 중단을 하나의 규칙으로 통일 — 구간 0부터 훑으며
  완료 구간은 통째로, **첫 미완료 구간은 그때까지만** 넣고 멈춤. 결과적으로 맨 앞부터
  연속된 prefix까지만 반영(중단 시에도 화면에 구멍 없음).
- **parallel_scan**: `rayon::par_iter`로 코어 수(`available_parallelism`)만큼 구간
  분할 동시 스캔, `AtomicU64`로 진행 바이트 합산 → 상태바 실시간 반영.
- **prime**: 맨 앞 2MB를 즉시 순차 스캔해 첫 화면 보장(프라이밍) → 병렬 완료 시
  `replace_offsets`로 전체 결과 교체. 병렬은 파일 여기저기를 동시에 채우므로
  프라이밍 없이는 첫 화면이 늦어질 수 있어 명시 단계로 분리.

### memchr(SIMD) 전환
초기 병렬화만으로는 speedup이 1.8배에 그쳤다(바이트 단위 비교가 병목). `scan_segment`의
바이트 루프를 **memchr(SIMD/워드 단위 개행 탐색, ripgrep도 사용)**로 교체:
- UTF-8/CP949: `memchr_iter(0x0A, slice)` 직행
- UTF-16(step=2): 패턴 내 `0x0A`의 위치(lf_off)로 패턴 시작을 역산해 전체 검증
  (LE=`[0x0A,0x00]` lf_off=0, BE=`[0x00,0x0A]` lf_off=1)

### 성능 (64코어, 인메모리 1GB, 현실적 행 폭 ~90B)
| | 처리량 | 1GB | 환산 |
|---|---|---|---|
| 순차(memchr) | 8.7 GB/s | 123ms | — |
| **병렬×64(memchr)** | **15.7 GB/s** | **69ms** | 7GB≈0.45s, 10GB≈0.64s, 40GB≈2.5s |

병렬 speedup이 ~1.8배로 보이는 건 순차가 이미 memchr로 매우 빠르고 절대 처리량이
메모리 대역폭에 근접했기 때문. 실전(mmap)에서는 페이지 폴트가 코어별로 분산돼 이득이 더 큼.

### 중단/재개 의미 변경
- **중단 = 취소**: 병렬 워커가 pause 감지 시 즉시 멈추고, 연속 prefix까지만 남긴 채
  `Paused`. 40GB 같은 초대형 파일에서 앞부분만 보려는 용도.
- **이어서 읽기 = 처음부터 재스캔**: 병렬 중간 재개는 구간별 진행 추적/병합이 복잡해
  포기. 어차피 병렬이 빨라 재스캔 비용이 작음.

## 2. 뷰 모드(텍스트/표) + 커스텀 구분자

### 동기 (사용자 요청 1~3번)
1. 구분자 없는 형식(일반 텍스트/JSON/로그)은 그냥 텍스트 뷰어처럼 표시
2. 커스텀 구분자(임의 한 글자) 지원
3. 구분자 있는 형식도 텍스트로 구분 없이 보기

세 요청이 사실상 하나로 묶임 — "구분자를 무엇으로 볼지"에 **'구분 안 함(텍스트)'**과
**'커스텀'**을 추가하면 셋 다 해결.

### 설계
- **`SeparatorMode { None, Char(u8) }`** (parse.rs) — 구분 모드를 타입으로. 기존
  `Document.delim: u8` → `sep: SeparatorMode`.
- **자동 감지**: `detect_delimiter` → `detect_separator`. 확장자 우선(csv/tsv/psv),
  아니면 내용 분석. **어떤 표준 후보(, \t | ;)도 줄당 평균 1회 미만이면 None** 반환 →
  txt/json/log가 자연히 텍스트 뷰로 열림.
- **툴바**: 구분자 드롭다운에 "구분 안 함(텍스트)" 항목 + "직접:" 한 글자 입력란
  (`TextEdit char_limit(1)`, 비우면 텍스트 모드로). 헤더 체크박스는 표 모드에서만 표시.
- **렌더 분기**: `render_table`(라인번호+필드 컬럼, 기존) / `render_text`(라인번호+줄
  전체, 2컬럼). 디코딩 단계는 `decode_logical_line`(줄 전체) / `parse_logical_line`
  (필드 분리)으로 분리해 공유.
- **인덱싱은 모드와 무관**: 개행 offset 병렬 스캔은 그대로 재사용. 모드는 렌더링에만 영향.
